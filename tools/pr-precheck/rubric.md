# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| diff-matches-plan-scope | the diff's changed files and behavior, read against the plan's named files, its in-scope/not-in-scope statement, and any deviation notes recorded in the plan | every changed file and every behavior change in the diff falls inside the plan's stated scope, or is covered by an explicit deviation note recorded in the plan itself (not only in the PR description); fails if the diff adds anything the plan did not scope in (an unannounced config option, a rewrite of a file the plan never names, a drive-by rename) with no deviation note, or if it leaves out a change the plan promised with no deviation note explaining the gap | required |
| description-matches-diff | the PR description's claims about what changed ("implements the plan exactly", "no changes beyond the plan", "now documents X"), read against the actual diff hunks | every fidelity claim the description makes is verifiable directly in the diff; fails if the description claims more than the diff delivers (a docs update, a behavior, a disclosure it doesn't contain) or claims the change is scoped to the plan while the diff contains an untouched-on-claim file or hunk | required |
| test-evidence-decisive | the test-evidence section, read against the plan's test plan (its named repro steps and expected-after) | the evidence shows a concrete before/after tied to the specific repro the plan named (an observed failure, then the observed fix, or an exit code / output change named) and states the outcome of the repo's own checks or suite that were actually run; fails on an assertion with nothing observable named ("tested locally, works now", "verified working for a day") or on a suite outcome that is asserted but never shown | required |
| test-evidence-on-target | the specific behavior the test evidence (and any new regression test named in the diff) exercises, read against the code path the diff actually changed and every distinct failure mode the plan's "Test plan:" sentence explicitly names as something to re-run | every failure mode or repro the plan's "Test plan:" sentence itself (not the scope or files list) explicitly names is addressed *somewhere* in the package — a before/after transcript, or a specifically named regression test in the diff whose passing outcome is stated — even if that outcome is only reported as "unchanged" or "passes" rather than a full transcript; fails only when a named failure mode has no corresponding transcript, named test, or stated outcome anywhere in the diff, description, or test evidence (silence), or when the evidence substitutes a different, already-working code path in its place; it does not fail merely because the fix's scope touches more than one function or file while the test-plan sentence names only one repro, and it does not fail merely because a named item's confirmation is terser than another's | required |
| diff-reviewable | the unified diff's hunks and the commit list | the diff contains only what the fix (and its necessary tests, docs, or changelog entry) requires; fails if any hunk is a debug print or eprintln, commented-out code, a first-attempt block left in, a dead function kept behind an unused/dead-code marker, a pure formatting or re-indentation pass, or an unrelated drive-by edit, even when the core fix inside the same diff is correct; a commit list of vague labels ("wip", "fix", "misc cleanup", "fmt") is itself evidence the diff was never squashed clean | required |
| template-compliant | the repo-facts block's stated required PR-template sections or checklist, read against the PR description and the diff | every section or checklist item the repo's template requires has real, specific content addressing this PR (not left blank, not a copy-pasted boilerplate line); fails if a required item is visibly unaddressed, including a required changelog/whatsnew entry that the template asks for but the diff does not contain | required |
| ai-disclosure-compliant | the repo-facts block's stated AI-use or contribution policy, read against the PR description | when the repo's stated policy requires disclosing AI assistance, the description contains an explicit disclosure statement in the author's own words naming the assistance; every package this tool grades is AI-assisted work by default, so a description that simply never mentions AI is a fail, not a pass by default, whenever disclosure is required; when the repo states no AI policy at all, this check passes regardless | required |

## Verdict rule

Accept (ready to submit) if and only if every required check passes. There
are no preferred checks on this rubric; every row above gates the verdict,
because each one is load-bearing for one of the four ways a PR fails that
this tool must be able to see. A grade of `unclear` counts as a fail: a
claim this tool cannot verify from the package (or, live, from the branch
and the repo) is a claim that is not ready to submit on. When more than one
required check fails, the verdict is still a single `reject`; which check
gets quoted as the deciding one is procedure.md's call, not the rubric's.
